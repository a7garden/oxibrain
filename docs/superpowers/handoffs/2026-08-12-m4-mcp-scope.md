## 2. The MCP decision: in-house JSON-RPC (DESIGN §18 fallback)

**Problem.** `rmcp` 0.12–0.14 depends on `darling 0.23.0`, which requires Rust ≥ 1.88.
MSRV is deliberately pinned to **1.85** (`rust-toolchain.toml`, `rust-version`).
Latest `rmcp` (3.1.2) needs newer still. Bumping MSRV contradicts the standalone,
low-floor guarantee.

**Decision.** Implement the DESIGN §18 fallback verbatim: *"a minimal in-house
server over the same protocol types."* The MCP surface over stdio is
newline-delimited JSON-RPC 2.0 — small enough that a hand-rolled server is the
boring, coherent choice. **MSRV stays 1.85; `rmcp`/`schemars`/`darling` are gone.**

`oxibrain-mcp` now compiles at MSRV with **zero external protocol deps**.

## 3. Architecture: what was built

### `oxibrain-mcp` (rewritten — replaces the rmcp scaffold)

| Module | Responsibility |
|---|---|
| `protocol.rs` | JSON-RPC 2.0 message parsing + MCP response shapes. Error codes: standard (`-327xx`) + `UNAUTHORIZED = -32001`. 4 unit tests. |
| `server.rs` | `BrainServer` — 7 tools, `initialize`/`tools/list`/`tools/call`/`ping` dispatch, **scope enforcement**, stdio loop. 16 tests. |

**Protocol behavior:**
- `initialize` → negotiates version: echoes `2026-07-28` if requested, else `2025-11-25`. Advertises `tools` capability + `serverInfo`.
- `tools/list` → 7 tools with **hand-written JSON Schemas** (no `schemars` derive).
- `tools/call` → dispatches by name; structured results returned as pretty JSON text (agents can parse); write tools return short confirmations.
- `notifications/initialized` → no response (notification).
- Notifications and unparseable lines handled per JSON-RPC.

**The 7 tools** (DESIGN §12.2 table), all verified by tests:

| Tool | Capability | Brain method |
|---|---|---|
| `search` | Read | `query` (mode: hybrid/lexical/semantic/graph/community) |
| `recall` | Read | `assemble_context` |
| `get_entity` | Read | `beliefs` |
| `why` | Read | `why` |
| `contradictions` | Read | `contradictions` |
| `ingest` | Ingest | `ingest_note` |
| `declare` | Write | `declare` |

**stdio transport:** `BufReader::read_line` loop (avoids `tokio_stream`); one
response per line to `BufWriter<stdout>`, flushed each message. All diagnostics
to **stderr** — stdout is the protocol channel. `tokio` `io-util`+`io-std`
features added locally to `oxibrain-mcp` (workspace tokio untouched).

**Socket transport (`serve --socket <path>`):** the framing loop is factored into
`run_session(reader, writer)` — generic over `AsyncRead`+`AsyncWrite`, shared by
stdio and the Unix listener. `serve_socket` binds a `UnixListener`, clears a stale
socket file, and spawns a `run_session` task per connection over the shared `Brain`
(the store actor serializes writes — P8). `net`/`time` tokio features added locally.

### Scope enforcement (`server.rs`)

`BrainServer` carries `scope: Option<Scope>`:
- **`None`** (trusted local stdio via `from_brain` / `open`) → no gate. The local channel is trusted by design.
- **`Some`** (authenticated transport via `from_brain_scoped`) → `enforce_scope` runs before every dispatch:
  1. Capability gate (no side effects): `caps.contains(required)` + not expired → else `UNAUTHORIZED`.
  2. Space gate: resolve the content-derived space id, check `scope.spaces` membership → else `UNAUTHORIZED`.

`required_capability` maps tools per the §12.2 surface table. The gate is the
enforcement **point**; wiring it to a real token handshake is the daemon's job.

### CLI growth (`oxibrain-cli`)

| Subcommand | What |
|---|---|
| `oxibrain serve` | Open the brain and run the MCP server on stdio. |
| `oxibrain predicate-list` | Print the core/v1 registry (12 predicates, full semantics). No store needed — pure registry read. |
| `oxibrain extract <id>` | Synchronous single-episode extraction (realtime, calls LLM). |
| `oxibrain reextract` | Re-extract all uncached primary episodes (new extractor id; D8 cache preservation). |

`extract`/`reextract` share `cmd/llm.rs`: builds an `LlmPort` from env
(`OXIBRAIN_LLM_PROVIDER=anthropic|openai` + the matching `_API_KEY`/`_MODEL`),
selects `ExtractMechanism` per provider (Anthropic→ToolCall, OpenAI→JsonSchema),
and constructs the `ExtractorConfig`. No LLM = clear error, never a silent no-op.

Subcommand naming is flat kebab-case (`predicate-list`, matching the existing
`token-issue`/`token-list` convention). DESIGN §12.4's nested form
(`predicate list`, `token issue`) is a future clap-flattening refactor across all commands.

## 6. Key decisions

- **D-new-1 — In-house MCP, not rmcp.** MSRV 1.85 is load-bearing (standalone guarantee). rmcp's macro stack (darling/syn) demands 1.88+. DESIGN §18 sanctioned the fallback; the protocol is small enough that hand-rolling is the coherent choice, not a compromise.
- **D-new-2 — Tools return JSON, not prose.** Structured results (`RankingResult`, `ContextResult`, beliefs, `ExplainBlock`) serialize to pretty JSON text. Agents parse it; humans can read it. Avoids per-field formatting bugs the rmcp scaffold would have had (it used guessed field names that never compiled).
- **D-new-3 — Scope gate is the enforcement point; transport owns auth.** `enforce_scope` is transport-agnostic. Local stdio is trusted (no scope); the daemon attaches a scope from the verified token. Keeps P6 (surfaces are adapters) intact: the same `BrainServer` serves both.
