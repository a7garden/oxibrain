## 3. Architecture — What Was Built

### New crates
- **`oxibrain-llm-http`** — Anthropic (tool-use structured output) + OpenAI (json_schema
  mode) adapters behind `LlmPort`. Depends on `ports` + `reqwest` only.

### New core modules
- **`core/extraction.rs`** — `Claim`, `MentionRef`, `ClaimObject`, `ExtractionResponse`,
  `ExtractorConfig`/`ExtractMechanism`/`ExtractorId`, `schema_from_registry` (pure fn),
  `build_extraction_prompt` (pure fn), `validate_claims` (pure fn with 7 validation rules),
  `ValidationResult`/`ValidationError`, `ExtractSummary`, `ExtractionBudget`.
- **`core/confidence.rs`** — `ConfidenceComponents`, `CalibrationTable`, `calibrate()`,
  `derive_calibration()`.

### New ports
- **`FakeLlmPort`** — test-only `LlmPort` impl. Canned responses keyed by prompt substring.
  Used by integration tests and the future `fast` eval suite.

### New store modules
- **`store/extraction.rs`** — `IngestJob`/`JobState`, job queue CRUD (enqueue/claim/
  complete/fail/reclaim/list), response cache CRUD (cache/get), `project_extraction`
  (claims → assertions + mentions with real byte spans), `project_from_cache`
  (reproject path), `ingest_and_enqueue`, `uncached_episodes`.
- **`store/quarantine.rs`** — `ExtractionFailure`, `record_failure`, `list_failures`.
- **`store/consolidation.rs`** — `EpisodeCluster`/`CommunityGroup`, summary cache CRUD,
  `write_derived_episode`, `find_episode_clusters`, `build_consolidation_prompt`,
  `build_community_prompt`, `load_community_entities`, `hash_member_set`.

### Extended facade (`oxibrain/src/lib.rs`)
- Brain gains `Option<Arc<dyn LlmPort>>` + `with_llm()` constructor.
- **`ingest`** — creates Primary episode + enqueues extraction job.
- **`extract_one`** — full pipeline: read → schema → LLM (async, off-actor) → validate →
  repair loop → project (WriteOp).
- **`extract_pending`** — batch worker: claim jobs → extract_one each.
- **`reextract`** — re-extract with new extractor (cache preserved).
- **`consolidate`** — cluster episodes → LLM summarize → Derived episodes.
- **`summarize_communities`** — community groups → LLM summarize → Derived episodes.
- **`job_status`** — query job counts by state.

### Extended reproject (`store/reproject.rs`)
- Step 3.5: replays cached extractions via `project_from_cache` — maintains P1 byte-
  identical determinism with extraction-produced assertions.

### Extended BrainError (`ports/error.rs`)
- Added `Provider { retryable, message }`, `Extraction(String)`, `Budget(String)`.
- `retryable()` includes `Provider { retryable: true, .. }`.

## 4. Critical Patterns

### 4.1 LLM calls are ALWAYS off-actor (§7.2)

The writer actor runs all writes in transactions. LLM calls take seconds-minutes.
The Brain facade orchestrates: read [reader] → LLM [async] → write [WriteOp].
Store functions are synchronous, take `&Connection`, never call the LLM.

### 4.2 Extraction → assertion projection

`project_extraction` follows the M1 `project_declaration` pattern but with:
- Real byte spans (not fixed 0/100/200)
- `extractor_id = ExtractorConfig::id()` (not "declaration")
- `confidence` from the LLM (not 1.0)
- `valid_from/_to` from claim or sentinels (TIME_MIN/TIME_MAX)

### 4.3 Fabricated-entity gate

The validator checks that each mention's `surface` appears verbatim at `[span.0, span.1)`
in the episode content. A fabricated name not in the text cannot pass. This is structural
— no eval needed to enforce it. Tested in `m3_extraction.rs::fabricated_entity_rejected`.

### 4.4 Reproject determinism with extraction

Extraction responses are cached in the `extractions` table. Reproject reads the cache
and re-projects via `project_from_cache` — no LLM call. The canonical replay order is
`(episode.seq, extractor_id)`. Tested in `m3_extraction.rs::reproject_byte_identical_with_extraction`.

### 4.5 Dependency pin for rustc 1.85

`idna_adapter` was pinned to 1.1.0 (down from 1.2.2) because ICU 2.x requires rustc 1.86.
The pin is in `Cargo.lock`. If `Cargo.lock` is regenerated, re-apply:
`cargo update -p idna_adapter --precise 1.1.0`.

## 5. What Remains for M3d

### 5.1 Eval harness (`eval/` crate)

Create a workspace member crate with:
- `EvalMetrics` — fabricated_entity_rate, statement_precision/recall, resolution_f1.
- `EvalRunner` — ingests golden corpus fixtures, extracts via FakeLlmPort, compares.
- `fast` suite — fixture-replayed, no network, every PR.
- `full` suite — live provider, nightly/manual.

**Status:** Types exist in `core/confidence.rs` (`derive_calibration`). The eval runner
itself is not yet built.

### 5.2 Golden corpus fixtures

~10-15 JSON fixtures in `eval/corpus/{en,ko}/` with:
- Episode content (note, document, agent-trace shapes; EN + KO)
- Expected entities (surface, type, span)
- Expected claims (predicate, subject, object, polarity)
- ~5 questions with reference answers

### 5.3 Budget measurement

Run `cargo bench -p oxibrain` and record §13.2 numbers. The bench suite exists (M2);
numbers haven't been measured. Each budget may be revised once (D16).

### 5.4 CLI subcommands

- `oxibrain extract [--space S]` — runs extract_pending.
- `oxibrain reextract [--space S] --extractor ID` — re-extracts.
- `oxibrain eval --suite fast|full` — runs eval suite.

### 5.5 §14.2 regression tests

Tests that assert metrics meet quality gates:
- fabricated_entity_rate == 0.00 (structural)
- statement_precision ≥ 0.90
- statement_recall ≥ 0.70
- resolution_f1 ≥ 0.92
