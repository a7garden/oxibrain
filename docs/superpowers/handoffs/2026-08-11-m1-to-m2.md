## 2. Phase M2 Scope

**M2 — Retrieval and lifecycle. Still deterministic (no LLM).** Per DESIGN §17: indexes (FTS5/BM25, sqlite-vec, HNSW in-memory, adjacency), hybrid query with RRF, bounded traversal, salience decay, compaction, community clustering (label propagation — deterministic; summary *text* waits for M3), `assemble_context`, `why`, `timeline`, `diff`, `why --dropped`, and the committed bench suite measuring the §13.2 budgets.

**Exit (DESIGN §17):** budgets measured and either met or revised **once** with recorded evidence; multi-hop and thematic queries answer over a hand-built graph.

### ⚠ Critical reconciliation (discoveries in M1 that change M2)

1. **Bench suite gap.** DESIGN §13.2 says "a committed bench suite measures them **from M1**" — but M1 shipped no bench infra (M1 was correctness-only). M2 MUST build the bench suite FIRST and measure the §13.2 budgets, then either meet them or revise each budget once with recorded evidence. This is an explicit M2 deliverable, not optional.
2. **Spaces-ID vs spaces-name API gap.** `Brain::ensure_space("x")` returns a **content-derived ID** (blake3 of name), and projection rows FK on that ID. Callers (`declare`, `contradictions`, etc.) must pass the **ID**, not the name. Passing the name silently fails in the writer (error only visible via `tracing::warn!` with no subscriber). M2's new query methods (`timeline`, `diff`, `why`) must accept and document the space ID. Consider whether the facade should accept a name and resolve it — a usability decision to make deliberately.
3. **Confidence is a placeholder in M1.** The fold sets `confidence = 1.0` for all declarations (no extractor, no calibration — that's M3). M2 must NOT rely on confidence for ranking as if it were real; retrieval ranking uses salience (P5), not confidence. Confidence calibration arrives in M3.
4. **`oxibrain-index` crate does not exist yet.** DESIGN §15 lists it (FTS5, sqlite-vec, HNSW, RRF). It must be added as a new workspace member in M2. It may depend on `store` (to read projection) and `ports`; never the reverse.
5. **Graph context in resolution is stubbed.** `resolve_or_create` passes `|_| 0.0` for graph context. M2's adjacency gives the real shared-neighbor score — wire it if resolution is revisited, but note M2's resolution is not a focus.

## 3. Data Source Mapping

### 3.1 `core::retrieval` (new) / `store::query` (extend) — hybrid query + traverse

**Source:** projection tables — `beliefs` (status=active, confidence), `statements`/`assertions` (provenance), `entities`/`entity_keys` (names, adjacency), `episodes` (lexical content).

| Retrieval mode (§9.1) | Reads | Writes | Deterministic |
|---|---|---|---|
| `lexical` | FTS5/BM25 over episodes + statement renderings | index rows (rebuildable) | yes |
| `semantic` (M2 baseline) | TF-IDF vectors (offline, deterministic); dense GGUF is M3 | `oxibrain-index` vectors | yes (TF-IDF) |
| `graph` | adjacency from `statements` subject/object | — | yes |
| `community` | label-propagation clusters + (M3) summaries | `communities` table | clustering yes; summary text M3 |
| `hybrid` (default) | RRF fusion of the above | — | yes |

### 3.2 `store::lifecycle` (new) — decay + compaction

**Source:** `beliefs`, `statements`, `episodes` (cold content). Decay adjusts **retrieval salience only** (P5 — never belief truth). Compaction moves cold episode content to a compressed column in SQLite (keeps row/hash/links). Both are deterministic `WriteOp`s.

### 3.3 `core::context` (new) — `assemble_context`

**Source:** hot/warm/cold packing policy over pinned facts + high-salience beliefs + neighborhood + recent episodes, packed to a token budget (DESIGN §9.5). This is the function that lets `oxios` delete its memory code in M5.
