### Patterns to reuse in M3

| M2 pattern | M3 analog |
|---|---|
| Pure algorithms in `oxibrain-index` (RRF, TF-IDF, kNN, label-prop) — property-tested, no rusqlite | Extraction JSON schema generation as pure fn in core (registry → JSON Schema); validation as pure fn in core |
| Store orchestrates: calls index algorithms + rusqlite in WriteOps | Store orchestrates extraction: calls LlmPort outside transactions, writes assertions inside transactions |
| `rebuild_indexes(conn, space)` — deterministic rebuild from projection | `reextract(conn, extractor_id)` — deterministic re-extraction from cached responses |
| Index rebuild is deterministic (snapshot test) | Extraction cache must be deterministic (same content + extractor → same assertions) |
| `Brain::rebuild_indexes` via mpsc + writer.flush | `Brain::reextract` via mpsc + writer.flush (but extraction runs OFF the actor thread — LLM calls must not hold the writer) |
| TF-IDF model rebuilt from corpus on each index rebuild | Extraction cache keyed by `(content_hash, extractor_id)` — reprojection reuses cache |
| Facade `Brain::query` — `spawn_blocking + readers.read` | Facade `Brain::ingest` — submit to job queue, extraction runs off-actor |

## 2. Phase M3 Scope

**M3 — Extraction and evaluation. The LLM arrives.** Per DESIGN §17: job queue,
LLM port + HTTP adapter, registry-generated schema, forced structured output,
validator, repair and quarantine, mention capture, extractor identity,
re-extraction, budgets and backpressure, consolidation and community summaries

**Exit (DESIGN §17):** a real note corpus produces a graph meeting §14.2 gates;
benchmark numbers published for reference and default configurations; `reextract`
with a second model is comparable on the eval suite.

### ⚠ Critical reconciliation (discoveries in M2 that change M3)

1. **Extraction must run OFF the writer actor.** M2 established that all writes
   go through the writer actor's `WriteOp` closures. But LLM calls take
   seconds-minutes and must NEVER hold the writer connection. The extraction
   pipeline must: (a) claim a job off the queue, (b) call the LLM OUTSIDE any
   transaction, (c) validate the output, (d) submit a `WriteOp` that writes the
   assertions + mentions in one transaction. The `ingest_jobs` table (v1.sql)
   already exists with state/attempts/lease tracking.

2. **Extraction cache already has a table.** `extractions` (v1.sql) is keyed by
   `(episode_id, extractor_id)` with `response_hash` + `raw_response`. M3 uses
   this directly. Re-extraction with a new `extractor_id` creates a new cache
   entry; the old one stays for comparability.

3. **The predicate registry is ready for schema generation.** `PredicateDef`
   (M1) has `object_kind`, `cardinality`, `temporality`, `invalidation`,
   `symmetric`, `inverse_of`. M3 generates the extraction JSON Schema from this
   — one source of truth (P4). The schema constrains the LLM to valid
   predicates and object types.

4. **The `extraction_failures` table already exists.** M3's quarantine writes
   here: invalid LLM output, schema violations, repair attempts exhausted. The
   `extraction_failures` table (v1.sql) has `episode_id`, `extractor_id`,
   `raw_response`, `errors_json`, `created_at`.

5. **TF-IDF baseline is in place — dense embeddings arrive in M3.** M2 deferred
   sqlite-vec and HNSW to M3. M3 should add `oxibrain-embed-local` with GGUF
   dense embeddings behind `EmbeddingPort`. The `EmbeddingPort` trait already
   exists in ports (empty stub). Dense embeddings plug into the existing
   `KnnIndex` interface (swap TF-IDF vectors for dense vectors).

6. **Confidence is still a 1.0 placeholder.** M2 ranking uses salience, not
   confidence. M3's extraction pipeline produces real confidence values from
   the LLM, and the eval harness calibrates them (§6.5 calibrate fn skeleton).

7. **Community summary text is M3.** M2 built clustering (deterministic); the
   summary text is an LLM-generated `Derived` episode with cached text (§5.3).
   The `summaries` table already exists (v1.sql) keyed by
   `(scope_kind, member_set_hash, extractor_id)`.

8. **`source_kind` / `source_ref` in episodes are strings.** M2's FTS indexes
   episode content directly. M3's extraction reads episode content and
   produces structured assertions. The extraction pipeline does NOT modify
   episodes — it reads them and writes assertions + mentions.

9. **`resolve_entity_id` was added to Brain in M2.** This was an adaptation —
   the plan's `entity_id_for` helper didn't work because `entity_id()` takes
   `(space, entity_type, first_episode_id, span_start)`. M3's extraction will
   need entity resolution from mentions — the existing `project_declaration`
   resolution path (`resolve_or_create`) is the reference.

## 3. Data Source Mapping

### 3.1 `core::extraction` (new) / `store::extraction` (new) — extraction pipeline

**Source:** `episodes` (content), `predicates` (registry → schema), `extractions` (cache).

| Stage | Reads | Writes | Deterministic |
|---|---|---|---|
| Schema generation | `predicates` table | JSON Schema (in-memory) | yes (pure fn of registry) |
| LLM call | episode content + schema | `extractions` cache row | no (LLM) — but cached |
| Parse + validate | `extractions.raw_response` + schema | `extraction_failures` (on invalid) | yes |
| Assertion projection | parsed claims | `assertions`, `mentions`, `statements` | yes (same as declaration projection) |
| Entity resolution | `entity_keys` + `entities` | new entities/keys | yes (lexical resolution from M1) |

### 3.2 `store::extraction` (new) — job queue

**Source:** `ingest_jobs` table (already exists).

The job queue lifecycle:
1. `ingest` creates an episode + an `ingest_job` (state=ready).
2. A worker claims the job (state=leased, lease_until=now+timeout).
3. Worker calls the LLM (off-actor), validates, writes assertions.
4. On success: state=done. On failure: state=ready (retry, attempts++).
5. After max attempts: state=failed → `extraction_failures`.

## 8. Risks & Gotchas

| Risk | Status | Follow-up |
|------|--------|-----------|
| Budget numbers not yet measured | deferred to M3 | Run `cargo bench`, record numbers, revise §13.2 once max |
| LLM call holds writer actor | design constraint | Extraction MUST run off-actor; only assertion writing is a WriteOp |
| Extraction breaks reprojection determinism | not yet addressed | Extraction cache makes reproject deterministic (no LLM call); verify with extended byte-identical test |
| Dense embeddings change kNN performance | deferred | M2 uses brute-force cosine; M3 may need HNSW for dense vectors at scale |
| Schema generation complexity | not yet addressed | Start with a simple schema (predicates + object types); iterate with eval data |
| `EpisodeKind::Derived` feedback loop | design constraint | Community summaries write Derived episodes; NEVER extract from them (§5.3) |
| Consolidation writes Derived episodes | design constraint | These must be terminal — cached text, never re-extracted |
